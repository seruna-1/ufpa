# Modelo para Desenvolvimento de um Ambiente de Usuário baseado em Linux

Prototipagem inicial para a interface gráfica, depois modelo RAD para desenvolvimento da primeira versão das bibliotecas de sistema. O desenvolvimento de cada contexto dentro API da biblioteca de sistema (interface gráfica, persistência, preferências, comunicação interprocesso e assim por diante) segue seu próprio fluxo sequencial de implementação de acordo com a visão geral estabelecida após a fase de prototipação.

Com a primeira versão estável da biblioteca de sistema disponível, o desenvolvimento dos programas começa seguindo o modelo incremental. Os requisitos das aplicações são escolhidos para atender, primeiramente, o básico do que outras alternativas já atendem. Depois, o desenvolvimento das aplicações entra no modelo incremental para implementar funções mais complexas gradualmente.

Ao passo que cada aplicação do sistema atingir maturidade funcional, o desenvolvimento passa para o modelo espiral. Depois da primeira versão, o desenvolvimento da biblioteca gráfica de sistema passa para o modelo evolucionário, recebendo feedback dos usuários e melhorando constantemente ao longo de lançamentos intermediários, e eventualmente versões estáveis. Já as aplicações do sistema que forem atingindo maturidade suficiente saem do modelo incremental para o modelo espiral, com as espirais sincronizadas com as versões estáveis do sistema: assim que uma nova versão estável do sistema é lançada, o código da aplicação é readequado à nova API preservando as funções existentes, depois novas funções podem ser adicionadas já adequadas à nova interface, e , por fim, o desenvolvimento entra em modo de manutenção, com correção de bugs, até que a estrutura do ambiente seja novamente atualizada e o processo reinicie.
